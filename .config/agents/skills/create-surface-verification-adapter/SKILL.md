# Create Surface Verification Adapter

Manual wrapper for an approved consuming repository. Load `surface-verification-adapter` first. Delegate skill-file authoring mechanics to `craft-skill`; keep eligibility, proposal, approval, proof semantics, and product behavior here.

## Eligibility

Inspect the consuming repository read-only. Resolve only its declared repository-owned skill seam. Never hardcode `.cursor/skills`, `.grok/skills`, `.omp/skills`, or another provider directory.

Create only when repeated live-behavior proof needs one durable, distinct launch, isolation, drive, evidence, and cleanup contract. Decline with no artifact when native tests, static or build checks, measurement, a task-local recipe, or an equivalent existing adapter is sufficient. This dotfiles repository is a library/config decline case and receives no product adapter.

Use the default name `surface-verification-<approved-lifecycle-slug>` unless the repository declares a nonconflicting skill naming convention. One adapter may cover multiple visible entry points only when all five mechanics are compatible.

## Exact proposal and approval

Before any write, return one exact proposal containing:

- final adapter root and name;
- every file and effect;
- absent or SHA-256 baseline for every affected path;
- ownership and preservation boundary;
- exact manual frontmatter, including `disable-model-invocation: true`;
- all required shared-contract sections and at least one real stable path; and
- end-to-end validation for launch, doctor, drive, evidence survival, and cleanup.

Only the human response `approve` to the unchanged complete proposal permits mutation. Any other response, proposal change, expired context, affected-path drift, or changed preservation fact writes nothing and requires a new proposal. A fixture's synthetic `approve` is test evidence only and never authorizes a real repository.

## Authoring delegation

After exact approval and a complete pre-write baseline recheck, invoke `craft-skill` with exactly one caller-owned tuple:

```text
approved adapter root; exact file manifest; manual frontmatter; required sections;
absent/current baselines; preservation boundary; validation recipe
```

`craft-skill` owns only skill-file authoring, evaluation, and the exact changed manifest. It cannot decide eligibility, approval, adapter naming, acceptance, maintenance classification, product repair, or shipping. Reject a returned path outside the approved manifest or any ownership change.

## Validation

Validate the final tree with the shared `scripts/adapter_contract.py adapter --root PATH`. Exercise launch and readiness, doctor cleanup, one stable real path and resulting state, evidence survival after cleanup, isolation, and the complete cleanup contract. Rehash the final tree after all generated bytes settle and bind later recipes only to that final URI and digest.

A broken checkout, host command, or product returns `blocked` with direct evidence. Never repair product code, create an empty adapter or feature map, stage, commit, push, open a pull request, release, deploy, or ship.

## Result

Return exactly `changed | unchanged | blocked`, the approved root, final changed manifest, final adapter URI/digest when present, proof evidence, cleanup state, and any exact resume condition. `unchanged` requires an already-equivalent current adapter; do not duplicate it.
