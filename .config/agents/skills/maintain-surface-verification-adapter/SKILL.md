# Maintain Surface Verification Adapter

Manual wrapper for one exact existing repository adapter. Load `surface-verification-adapter` first. Delegate skill-file mechanics to `craft-skill`; keep eligibility, classification, proof, and product boundaries here.

## Intake

Require one exact existing adapter `file://` URI and `surface-verification-adapter-tree/v1` digest plus one eligible predicate:

- proven stale doctor or drive guidance;
- current approved adapter-upkeep scope;
- explicit full adapter audit; or
- a complete authorized `continual-learning assess` candidate for this already-existing destination.

Source proximity, adapter age, possible usefulness, ordinary verification, generic upkeep, a product failure, and an absent destination are ineligible. Portable `assess` may update this already-authorized adapter destination but may not create any adapter, shared contract, or wrapper.

## Classification

Bind and rehash the current adapter before mutation. Distinguish:

- documentation drift: adapter-owned instructions no longer match the proven surface;
- harness gap: adapter-owned launch, drive, evidence, isolation, or cleanup guidance is incomplete; and
- product regression: the target product violates its expected behavior.

Only the first two are adapter maintenance. Product regression remains direct product evidence and is never repaired here.

## Authoring delegation

Freeze the exact adapter-owned path set, current baselines, preservation boundary, approved change, and re-drive recipe. Shared live driving is serialized. Pass `craft-skill` exactly one caller-owned tuple:

```text
approved adapter root; exact owned file manifest; manual frontmatter; required sections;
current baselines; preservation boundary; validation recipe
```

`craft-skill` may edit only the existing adapter-owned files and returns the exact changed manifest. It cannot create another destination, decide eligibility, weaken manual invocation, alter acceptance or proof ownership, repair product code, or ship.

## Re-drive and rebind

Revalidate the final tree with the shared `scripts/adapter_contract.py adapter --root PATH`. Re-drive every changed path, prove evidence survival and cleanup, then bind the final URI/digest. Every proof recipe naming the prior digest must be rebound before later assurance. Post-bind drift makes assurance `INCONCLUSIVE`; it does not authorize a maintenance loop.

## Result

Return exactly `changed | unchanged | blocked` with classification, baseline/final adapter identity, exact changed manifest, re-drive evidence, cleanup state, affected recipe rebind requirement, and resume condition. Perform no product edit, staging, commit, push, pull request, release, deployment, or shipping.
