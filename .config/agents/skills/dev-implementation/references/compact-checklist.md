# Compact implementation checklist

Apply every item before accepting compact completion:

1. Bind the invoking agent as controller, approved intent, acceptance IDs, one exact child owner, owned paths/surfaces, permitted effects, applicable project instructions, and the child's concrete receiver identity. Use a planless direct contract unless an already-approved lean plan is required by dependency or recovery needs. Standalone and router entry both use the invoking controller in place; a separate controller requires an explicitly approved topology.
2. Confirm the work is settled, reversible, one-lineage, free of independent-proof requirements, and covered by deterministic direct checks. Any material ambiguity, destructive/external effect, fan-in, or independent-assurance need disqualifies compact.
3. Dispatch all code-changing work to the child. The controller validates and schedules only. Missing transport capability that cannot preserve required ownership or same-child follow-up is `transport-unavailable`; a concrete failed invocation is assessed under the shared recovery policy before escalation. The controller never downgrades, substitutes ownership, or recursively delegates another controller.
4. Preflight an explicit caller-selected response-object schema, resumable same-child transport and exact controller/child/launch-job/task/attempt/`candidate` bindings. The child terminal-completes its type-absent candidate before final smoke or Handoff, without incremental publication or parking. Retain the exact original launch result and row, validate and decode the adapter-designated data, and admit exact candidate identity. Then bind child/controller/task/attempt/operation/logical-Handoff/phase/schema/invocation and send `~/.agents/references/impl-rethink/impl-rethink.md` through the portable host-selected seam. This exact collection uses the `dev-implementation` owner-directed return-preflight exemption. The child applies code then test rethink, at most one correction, all direct checks and changed-path smoke, and returns one lean Handoff. Collect each follow-up through the loaded host adapter's collection rules and admit exact report identity once. Job settlement is neither task completion nor disposal.
5. If execution machinery fails or would otherwise cause an execution-related blocker, keep the same execution owner and assess `skill://dev-implementation/references/execution-recovery.md` before escalation. Explicitly apply its recovery rethink only before an eligible retry, retain failed evidence, cause, and allowance in the lean Handoff, and keep this separate from the single implementation rethink and semantic attempts. Collection of an already-authorized recovery return from the same bound child uses the `dev-implementation` owner-directed return-preflight exemption. Custom collectors retain their own preflight.
6. Apply `skill://dev-implementation/references/test-value.md` as the sole permanent-test policy for every changed or proposed permanent test. Do not inspect unrelated portfolio tests.
7. Papercut accounting follows the papercut scheduling rule.
8. End the route only after the remaining approved outcome completes. Compact assurance is per `dev-implementation` Assurance. An in-place controller consumes the child return and finishes without a self-Handoff; an approved delegated controller alone returns across its real boundary to the concrete route owner. A failed check stops only after the shared policy identifies no permitted execution recovery; unavailable required ownership and explicit exhausted limits remain stops.
