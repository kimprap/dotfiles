# Compact implementation checklist

Apply every item before accepting compact completion:

1. Bind the invoking agent as controller, approved intent, acceptance IDs, one exact child owner, owned paths/surfaces, permitted effects, applicable project instructions, and the child's concrete receiver identity. Use a planless direct contract unless an already-approved lean plan is required by dependency or recovery needs. Standalone and router entry both use the invoking controller in place; a separate controller requires an explicitly approved topology.
2. Confirm the work is settled, reversible, one-lineage, free of independent-proof requirements, and covered by deterministic direct checks. Any material ambiguity, destructive/external effect, fan-in, or independent-assurance need disqualifies compact.
3. Dispatch all code-changing work to the child. The controller validates and schedules only. Missing transport capability that cannot preserve required ownership or same-child follow-up is `transport-unavailable`; a concrete failed invocation is assessed under the shared recovery policy before escalation. The controller never downgrades, substitutes ownership, or recursively delegates another controller.
4. Preflight an explicit caller-selected declared response-object schema, resumable same-child transport, and exact controller/child/job/task/attempt/`candidate` bindings. The child returns its candidate through terminal type-absent ordinary completion without final smoke, Handoff, incremental publication, or parking. Collect only the exact completed job; immediately retain its complete original native result and matching job record, validate and decode only the adapter-designated structured data, and admit exact candidate identity. Then send `~/.agents/references/impl-rethink/impl-rethink.md` to that same child through a fresh-token awaited owner-directed request. This exact `dev-implementation` controller collection needs no additional consent, attendance, external-supervisor, or abort-capability preflight. The child applies code rethink, then test rethink, makes at most one correction pass, runs each direct check and the changed path, and replies on that request's message channel with one lean Handoff to the concrete controller. Job settlement is not task completion; yield, ordinary completion, missing awaited return, or a replacement child is not the Handoff.
5. If execution machinery fails or would otherwise cause an execution-related blocker, keep the same execution owner and assess `skill://dev-implementation/references/execution-recovery.md` before escalation. Explicitly apply its recovery rethink only before an eligible retry, retain failed evidence, cause, and allowance in the lean Handoff, and keep this separate from the single implementation rethink and semantic attempts. Collection of an already-authorized recovery return from the same bound child uses the same exact role-and-purpose preflight exemption; it gains no second implementation rethink, deadline, observer, replay, or replacement. Custom collectors retain their own preflight.
6. Apply `skill://dev-implementation/references/test-value.md` as the sole permanent-test policy for every changed or proposed permanent test. Do not inspect unrelated portfolio tests.
7. After the completed Handoff, the same child loads `papercut` once; the controller substitutes only if that child is unavailable.
8. End the route only after the remaining approved outcome completes. Compact dispatches no independent reviewer, verifier, learning assessment, audit, or second implementation self-rethink. An in-place controller consumes the child return and finishes without a self-Handoff; an approved delegated controller alone returns across its real boundary to the concrete route owner. A failed check stops only after the shared policy identifies no permitted execution recovery; unavailable required ownership and explicit exhausted limits remain stops.
