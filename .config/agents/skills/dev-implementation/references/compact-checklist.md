# Compact implementation checklist

Apply every item before accepting compact completion:

1. Bind approved intent, acceptance IDs, one exact child owner, owned paths/surfaces, permitted effects, applicable project instructions, and one receiver. Use a planless direct contract unless an already-approved lean plan is required by dependency or recovery needs.
2. Confirm the work is settled, reversible, one-lineage, free of independent-proof requirements, and covered by deterministic direct checks. Any material ambiguity, destructive/external effect, fan-in, or independent-assurance need disqualifies compact.
3. Dispatch all code-changing work to the child. The parent validates and schedules only; unavailable child transport stops rather than downgrading ownership.
4. The child produces a candidate without final smoke or Handoff. The parent then sends `~/.agents/references/impl-rethink/impl-rethink.md` to that same child once. The child applies code rethink, then test rethink, makes at most one correction pass, runs each direct check and the changed path, and returns one lean Handoff.
5. If execution machinery fails, keep the same execution owner and follow `skill://dev-implementation/references/execution-recovery.md` before another execution. Explicitly apply its recovery rethink before every retry, retain cause and allowance evidence in the lean Handoff, and keep this separate from the single implementation rethink and semantic attempts.
6. Apply `skill://dev-implementation/references/test-value.md` as the sole permanent-test policy for every changed or proposed permanent test. Do not inspect unrelated portfolio tests.
7. After the completed Handoff, the same child loads `papercut` once; the parent substitutes only if that child is unavailable.
8. End the route. Compact dispatches no independent reviewer, verifier, learning assessment, audit, or second implementation self-rethink. A failed check or remaining blocker without permitted execution recovery is reported and stops completion.
