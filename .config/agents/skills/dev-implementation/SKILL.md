# Engineering Implementation

Own execution topology, task projection, runtime state, attempts, recovery, evidence aggregation, and local completion. Do not redesign approved authority or copy leaf-stage procedures.

## Intake and immutable bindings

Accept one approved direct implementation contract or an approved parser-valid implementation Executor Plan bound to current governing authority, acceptance, targets, effects, and proof recipes. Reject missing, stale, conflicting, unbounded, non-observable, cyclic, unnamed, or capability-ineligible intake and return it to its authority owner.

Changed upstream bytes require semantic comparison. A change to authority, scope, acceptance, fixed contracts, dependencies, effects, capabilities, or proof invalidates affected descendants and creates a new Task Contract revision. Unrelated drift does not reset readiness or assurance.

Bind immutable `compact | standard | high-consequence` assurance before topology. Compact requires settled reversible one-context, one-lineage work with deterministic proof and no existing compact disqualifier. Read [`references/compact-checklist.md`](references/compact-checklist.md) before its first ready transition. Compact uses criterion-complete worker smoke as terminal proof and has no independent verification, review, or learning tail.

Every criterion binds one complete canonical `surface-proof-recipe/v1` object and exact `VR-...@sha256:...` identity: acceptance, proof class, target/environment, scenario, inputs, evidence form, adapter, fixtures, dependencies, isolation, cleanup, comparison, and finite current consumer map when applicable. `adapter: none` is complete. A bound adapter requires its exact canonical URI/tree digest and one readiness doctor; doctor evidence never satisfies smoke or assurance.

At the first ready transition, bind the exact applicable-project-rule and target manifests once. Later roles compare current bytes with those manifests; they never silently rebuild or broaden them.

## Direct and plan-backed execution

Planless direct work keeps the lean one-owner same-context lane. It binds a minimal Task Contract directly and adds one Context Pack only when ownership/context change or durable recovery requires transfer. Generic direct capability assessment may retain its existing contract-preserving `one-owner-sequential` result.

Every approved parser-valid implementation Executor Plan enters plan orchestration, including a compact work-only plan. Resolve the current repository plan, run `scripts/executor_plan.py validate PLAN`, bind its exact `executor-plan-validation/v1` result and digest, then read [`references/plan-orchestration.md`](references/plan-orchestration.md).

Bind the provider-neutral Orchestrator Role Profile and fresh launch attestation to the exact Task Contract, plan, and authority. Run `scripts/orchestrator_profile.py assess-plan-backed`. Plan execution begins only on `full-orchestration` with profile `downgrade` exactly `none`; any other result is `transport-unavailable`. A compact plan uses this gate and dispatches its authored work owner or owners as children while remaining compact and tail-free.

`PROMOTE-SERIAL-DEFAULT` selects full orchestration with runtime concurrency one by default. This is scheduling within the full profile, not a separate profile or downgrade, and supports no general efficiency claim.

## Plan root boundary

The plan-backed root is a pure mechanical control plane. It may validate and bind identities, project todos and task state, calculate the ready frontier, admit target/effect ownership, dispatch exact fresh children, record child identity and monotonic timing, observe and control the same child, validate bounded Handoff fields and artifact references, enforce target/effect boundaries, recover mechanically, perform plan and papercut bookkeeping, schedule the declared backend, invoke and validate the existing terminal archive operation as mechanical lifecycle bookkeeping, and prepare settled presenter input.

The root never edits a task target, performs a semantic task or repair, runs task smoke, inspects a child transcript, judges implementation sufficiency, conducts worker closure, performs an audit opinion or semantic review, weakens isolation, invents a task, or substitutes itself for a child. A plan transport failure never authorizes root rescue.

Project the authored task graph exactly. Do not add, split, merge, substitute, or hide a task. `Topology`, `Lineages`, `Isolation`, and `Fan-in` describe graph and proof boundaries, not root work permission. Direct `dev-integration` remains an unchanged specialty.

## Shared-tree scheduler

At each frontier:

1. Require exact declared targets, effects, dependency Handoffs, exclusive resources, and isolation needs.
2. Release only dependency-ready work. Mechanically disjoint ready ownership may overlap within the concurrency ceiling; declared overlap, unknown overlap, or an exclusive resource serializes.
3. Compare each child's writes and effects with its bound ownership. An undeclared mutation stops that child and invalidates affected descendants; it never broadens ownership.
4. Preserve authored isolation and neutral fan-in. When shared-tree transport cannot preserve either, stop `transport-unavailable` instead of weakening the plan. Portable compact and fan-in plans remain structurally valid.
5. Recheck target and dependency identities before result admission. Unexpected semantic drift is `authority-change-required`; unrelated user work is preserved.

## Task Contract

Bind before `ready`:

- parent `OUT-...`, exact authority, immutable assurance, topology, and one task revision;
- unchanged human Intent and `Methods: none | tdd` from the plan, or exact direct derivation authority;
- owned criteria and proof-recipe identities;
- declared targets, effects, dependencies, exclusive resources, isolation, and receiver;
- one complete solution-discipline order: reuse current code, standard library, native platform, installed dependency, minimum new code;
- attempt, repair-token, review, and applicable continuation-receipt state;
- exact worker-closure and test-value reference identities when work is dispatched;
- once-bound rule/target manifests and bounded environment facts.

`tdd` binds the current `dev-tdd` skill before readiness. `none` loads no method skill. A binding mismatch blocks before attempt consumption. Methods changes only worker procedure and creates no task, criterion, effect, assurance, or receiver.

## Context Pack

Use the existing Context Pack only across a context boundary and for every plan child. Include only:

- the unchanged Task Contract;
- owned criteria and proof recipes;
- governing authority and private-reference identities;
- declared dependency Handoffs;
- exact target/effect boundary;
- child/task/attempt identity and inherited repair state;
- applicable continuation receipt;
- bounded environment facts;
- native artifact locators;
- one exact receiver.

Exclude transcripts, broad repository summaries, unrelated files, a copied plan body, hidden state, and a second context or result schema.

## Worker procedure

A planless same-context attempt stays with its semantic owner. Each dispatched plan-backed attempt, eligible attempt two, and admitted Build repair uses its bound fresh child. In every shape, that same semantic owner:

1. Rechecks the Task Contract, dependencies, targets, and current manifests.
2. Reads the real changed flow, callers, and current local patterns.
3. Selects the first sufficient solution rung without reducing approved behavior, compatibility, safety, accessibility, or proof.
4. Implements only the declared contract and produces a nonterminal candidate.
5. Reports candidate readiness to the controlling implementation owner without settling tests, running final smoke, or sealing a Handoff.

## Same-child worker closure

The planless same-context semantic owner, each plan-backed task child, an eligible fresh-child attempt-two owner, and each admitted Build-repair worker use [`references/worker-closure.md`](references/worker-closure.md), identified as `worker-closure/v1` by its exact digest. The reference alone owns the exact challenge prompts.

Round one is mandatory through native same-child control and covers the four contract axes, first-sufficient ladder, candidate-local structural regression, and task-local permanent-test decision. Directly evidenced contract violations are admitted regardless of added complexity; quality correction requires the exact safe replacement or test disposition and preservation proof. Any actual admitted correction triggers round two, limited to corrected findings and plausible correction-caused regressions. There is no third round.

After permitted closure, the same semantic owner settles every changed permanent test under `test-value/v1`, or records the concrete existing-coverage/no-new-contract basis, then runs task-local smoke for every owned criterion, corrected finding, and correction-caused surface and emits exactly one Common Handoff. Verification, neutral integration, review, learning, audit controllers, and audit opinions never run worker closure.

Workers smoke the frozen acceptance cases, fixtures, oracles, and finite current consumers. Smoke results and worker conclusions are never independent verifier evidence.

## Permanent-test value

Apply [`references/test-value.md`](references/test-value.md) as `test-value/v1` to every changed permanent test:

1. Name an uncovered observable contract, regression, or invariant; without one, add no permanent test.
2. Find the closest existing test and extend or merge before adding.
3. Use the narrowest stable public seam and an independent oracle.
4. Name one plausible unique bug the test catches.
5. Reject or consolidate implementation-detail, tautological, duplicate, subsumed, incidental-snapshot, coverage-only, and production-logic-oracle cases.
6. Keep the smallest permanent set preserving every unique contract.

The work Handoff records one disposition row per changed permanent test, or the concrete existing-coverage/no-new-contract basis when tests do not change. Settle every row before final smoke. Explicit TDD keeps red/green evidence but consolidates redundant tracer tests before Handoff; closure never inspects untouched portfolio tests.

Before every assurance or completion boundary, recanonicalize each once-bound recipe and rehash each bound adapter. The final evidence binds the final adapter digest and final canonical recipe; drift blocks without consuming the boundary.

## Common Handoff and papercut accounting

Every attempt emits the existing Common Handoff from `dev-handoff` with the emitting role's local delta and exactly one receiver. A work Handoff additionally carries:

- exact child/task/attempt and before/after target identities;
- task outcome and criterion delta;
- `worker-closure/v1` digest, round count, finding IDs, corrections, dispositions, and final smoke;
- `test-value/v1` digest and changed-test rows or no-new-contract decision;
- applicable continuation receipt and changed falsifiable hypothesis;
- inherited attempt/repair/review state;
- papercut-accounting state.

After sealing the Handoff, the same work child performs exactly one current papercut soft look. The root falls back only when that child is unavailable. Retain all accounting in deterministic work-Handoff order. Completion projects only ordered material results into `papercuts`; none-only accounting yields `[]`.

The root accepts a Handoff mechanically only when child/task/attempt, dependency, target/effect, criterion-to-smoke, closure, permanent-test, receiver, and papercut-accounting fields match. It never converts that check into semantic acceptance.

## Attempts and continuation

Each Task Contract revision has attempt one and at most one eligible fresh-child attempt two. Attempt two requires attempt-one evidence of criterion progress, exact blocker resolution, or a materially changed falsifiable hypothesis already authorized under the unchanged contract. Its Context Pack includes the exact prior failure frontier and inherited run-wide repair state. Attempt three is forbidden.

After attempts exhaust 2/2, in the same parent session and turn that would otherwise present a continuation Ask, treat that draft Ask’s proposed continuation mechanism as the named candidate. Before presenting the Ask, bind the candidate’s materially changed falsifiable hypothesis, predicted discriminating observation, remaining blockers, and proposed cycle including exactly what the Ask would authorize, then explicitly load `skill://rethink` on that candidate. The candidate is the parent’s own draft mechanism, not a child transcript, Handoff restatement, packet for a fresh advisory child, or the exhausted worker’s context. Do not implement the candidate, spawn a rethink child, or load `rethink` for attempt two, Build repair, or any Ask outside post-exhaustion continuation.

Present only the complete corrected proposal returned by the loaded skill. If the skill returns no complete corrected proposal under its current contract, do not present the continuation Ask. This is a same-session quality gate on the parent’s human-facing Ask, not diagnosis or review of the child target, lifecycle authority, repair, smoke, closure, or Handoff admission. The root does not independently diagnose, grade, parse, or restate that result; it only gates presentation on the skill producing a complete corrected proposal.

After exhaustion, bare continue, elapsed time, another opinion, or an unchanged hypothesis changes no state. Only explicit human authorization naming the active plan and a materially changed falsifiable hypothesis creates one continuation receipt and a fresh attempt-one/two cycle. The receipt binds plan and target identities, blocked task, remaining criteria, hypothesis, authorizer/time, cycle, and inherited repair-token state. It uses the existing Context Pack and Common Handoff seam.

Failure preserves completed Handoffs and exact partial effects, stops the transitive dependency cone, cancels unsafe descendants, and leaves the plan `IN_PROGRESS`. Independent branches continue only when their authority, inputs, ownership, safety, and later integration remain unaffected.

## Assurance backend and repair

Compact ends after criterion-complete worker smoke and backend Handoff validation. Standard and high-consequence use the existing assurance backend. An authored valid optional final `dev-verification → dev-code-review → dev-continual-learning` suffix consumes those boundaries once; when omitted, the backend schedules the same boundaries once after the last accepted work Handoff. Earlier topology-required verification and direct neutral integration remain explicit.

Before any noncompact verifier dispatch, the backend natively resolves every current `file://`, `local://`, and `agent://` binding, retains live adapter-tree validation, and calls the import-only `validate_recipe_generation(...)` operation on the exact current acceptance-ID set, canonical recipe wrappers, and flattened current manifest bindings. A missing, stale, conflicting, unresolvable, or generation-invalid current binding is invalid intake with zero verifier dispatch and zero proof.

Cross-generation reuse is considered only after a last complete aggregate names the exact frozen prior acceptance set, recipe wrappers, manifest bindings, evidence, and their identities. The backend byte-compares that snapshot with the aggregate and validates the frozen prior generation without I/O or live prior rereads; current and prior generations are never unioned. A missing or inexact prior snapshot selects complete current all-fresh proof.

After both generations pass, the backend applies D02 before proof and freezes one typed row for every frozen criterion: `criterion → old recipe ID → new recipe ID → target-delta edge or none → fresh-or-reuse`. An edge is the ordered sequence of `(uri, old digest, new digest)` entries consumed by that criterion. A rebind is valid only when each changed binding names an approved edge, each edge URI already appears in both recipes, and the recipes are otherwise byte-equal; every valid rebound current recipe runs fresh and consumes no old-digest evidence. Exact unchanged identity with no edge is reuse-eligible only with exact prior evidence and independent verifier acceptance.

The deterministic dispositions are: a missing prior aggregate selects all-fresh; an ambiguous edge selects all-fresh; an approved semantic contract change selects all-fresh under the current contract; an unapproved non-digest semantic change returns `authority-change-required`; and a valid exact-delta/exact-no-edge set receives the typed rows above. No new action-map schema, recipe field, store, cache, ledger, compatibility reader, or result schema is added to make reuse available.

Across typed later-cycle and repair maps, the backend freezes one action for every parent criterion, and the verifier independently accepts or rejects every action before proof.

The run owns one post-assurance repair token. One blocking verifier or reviewer Handoff may consume it for one topologically ordered Build-repair cycle over only the original causally implicated task IDs. Each repair uses a fresh child, unchanged Task Contract, same-child worker closure, exact impacted smoke, and one Common Handoff. Re-run the last canonical projection owner whenever canonical projections change.

The current repair boundary remains exact: impacted proof runs fresh and exact unaffected evidence may be proposed for reuse. For every dispatched typed or repair action, the verifier independently repeats current resolution, current and frozen-prior generation validation, and action-map consistency; invalid current or dispatched reuse intake returns `INCONCLUSIVE` before proof without repair or silent downgrade. It independently accepts or rejects every action, runs every rebound or rejected-reuse current recipe fresh, and issues one fresh complete aggregate over every current criterion from fresh proof plus independently accepted exact-identity unaffected evidence.

After the last accepted work Handoff, obtain fresh current-target `dev-verification`, then one current-target `dev-code-review`, then terminal `dev-continual-learning`, unless an authored tail already consumes them. A repaired target receives fresh impacted proof and one review on its new identity.

Normal engineering completion is terminal and schedules no audit. `dev-test-audit` is a separate explicit `dev-ask` intake against its own exact frozen target and complete suite boundary; completed-plan provenance is optional. It is not an implementation task, assurance gate, worker-closure consumer, test-mutation authority, or completion transition. Its outcome changes no implementation lifecycle state.

## Completion

Complete semantic work only when all authored tasks, criteria, Handoffs, post-Handoff papercut accounting, required assurance, stable target identities, preservation controls, and applicable terminal learning are settled with no implementation blocker. The root performs accounting, the bounded terminal archive bookkeeping below when triggered, and presentation preparation only. The successful profile-specific presentation is terminal and dispatches no portfolio audit.

The terminal archive trigger exists only when the root's initial exact validation observed the active plan as `PENDING` or `IN_PROGRESS` and the same run changes that plan to parser-valid `DONE` or, with explicit human cancellation authority, `CLOSED`. The root retains that current-run fact in its bound execution state; it does not add a marker, infer ownership, scan terminal files, reconcile identity paths, or perform a historical sweep.

For `DONE`, finish all semantic work and settlement, all applicable required assurance, review, and learning, task and criterion records, Completion Summary, `Completed At`, and the exact parser-valid terminal bytes before invoking the existing archive operation. Validate success only when the active identity path is absent and the archive identity path is a regular non-symlink file byte-identical to that terminal snapshot. A current successful adapter archive result may satisfy the same postcondition without a second action. Only then may completion normalization and presentation proceed. This mechanical action is not an authored task, hidden tail, semantic-completion proof, Handoff, or presenter effect.

For current-session `CLOSED`, explicit human cancellation authority produces and validates terminal bytes without `Completed At` or a Completion Summary. Reach the same archive postcondition before one cancellation-close report; do not construct or emit completed presentation. Intake already at `DONE` or `CLOSED` performs no archive lookup, action, reconciliation, sweep, or mutation. Planless direct or compact work performs no repository-plan lookup, archive action or receipt request, or synthetic-plan creation and keeps its existing qualifying durable-summary boundary.

Both paths present, a divergent archive, parser-invalid terminal bytes, unsafe file kind, source or target drift, or an uncertain postcondition is a visible storage blocker. Preserve exact paths, kinds, and bytes; do not overwrite, blindly retry without changed evidence, continue semantic work, emit another Handoff, normalize or present completion, issue cancellation close, or speculatively revert terminal bytes.

Engineering completion normalization constructs exactly one current unversioned `completion-presentation-input` fence with the twelve ordered keys `status`, `outcome`, `change_scope`, `key_artifacts`, `verification`, `papercuts`, `learning`, `residual_risk`, `resume_from`, `handoff`, `constraints`, `next`. `change_scope` and `key_artifacts` are ordered one-to-three-item arrays; `papercuts` is the ordered array of material existing results, with `[]` projecting to the presenter-owned child `- none` and nonempty items projecting to consecutive `- ` children. The legacy `changed` key, scalar list values, and legacy singular papercut key are invalid. For planned completion, normalization begins only after the current archive postcondition validates, and `resume_from` is the identity-derived archive path followed by `@sha256:`, the lowercase SHA-256 of the exact archived terminal bytes, and `#completion-summary`. The same calling agent applies `completion-presentation`; the presenter is not dispatched.

Completion evidence includes the current plan and target identities; task/criterion/proof accounting; child and attempt identities; closure receipts; permanent-test dispositions; preserved parser/fixture identities when bound; assurance and review identities; papercut order; learning result; residual risks; ordered aggregate change scope; one to three durable key artifacts; for planned work, an immutable archived `#completion-summary` locator whose summary records outcome, material decisions, immutable evidence identities, current residual risk, and the exact target manifest reference; the existing immutable Handoff locator; `shipping not authorized`; and exact next authority. Exhaustive changed-path inventory stays in the target manifest and/or Handoff.

## Stops

Stop for unresolved human authority, material scope or route change, broken shared contracts, unavailable non-equivalent capability, unsafe partial effects, undeclared mutation, unpreservable isolation, exhausted attempts without a changed-hypothesis continuation receipt, consumed repair token with remaining blockers, stale evidence, a failed or uncertain terminal archive postcondition, or no progress. Never broaden targets, invent hidden repair, weaken topology, mutate tests from an audit result, infer shipping, retry storage without changed evidence, emit terminal output after a storage blocker, or substitute the root for a work child.
