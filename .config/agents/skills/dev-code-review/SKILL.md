# Engineering Code Review

Own one read-only Standards and Specification verdict for one immutable verified target and one backend-selected review slot when the assurance profile requires review. Compact is ineligible. Original-initial is the one whole-scope discovery pass and seals predicate-bound finding lineages. The backend then consumes original-rerun while it is `unused`; only after both original slots were already consumed may one current D03 human-grant identity admit exactly one grant-scoped post-`VERIFIED` pass for that cycle. Original-rerun and grant-scoped passes are closure and impact reviews, not fresh whole-scope discovery.

## Intake

Require the exact target identity; current `VERIFIED` Handoff and criterion evidence; target kind `final single-lineage | integrated with post-integration VERIFIED`; parent `OUT-...` and exact `AC-...` identities; inherited two-attempt/post-assurance repair state; original initial-review/rerun state; backend-selected review slot `original-initial | original-rerun | grant-scoped` and, for the last kind, one current D03 grant identity from the newest exhaustion record on the executing plan's same authoritative file; immutable standard or high-consequence profile and arrangement; verifier identity; governing requirements/specification/ticket revisions; the backend-validated once-bound applicable-project-rule and target manifests with canonical URI, exact SHA-256 revision/scope, and current byte-comparison results; every finite current consumer/callsite map required by a universal changed invariant; and the integration Handoff when fan-in occurred. Original-initial intake binds the whole declared review scope. Original-rerun and grant-scoped intake additionally bind the prior review receipt, every sealed lineage and remaining lineage, exact repair delta, accepted review impact map, affected and unchanged surfaces, required finite consumers, and exact original review evidence proposed for unchanged-surface reuse. Verifier receipts are evidence inputs, never the review verdict.

Require the verifier's exact canonical `surface-proof-recipe/v1` identities, each recipe's target and adapter binding, the current adapter-tree identities when present, and doctor receipt identities as readiness provenance only. Adapter presence never changes review eligibility, profile, independence, scope, slot, verdict policy, or repair budget.

Return `INCONCLUSIVE` for compact; a stale, partial, unverified, pre-integration-only, moving, or unnamed target; an omitted, rebuilt, extended, stale, mismatched, contradictory, or not backend-validated rule/target manifest; an incomplete finite-consumer proof; a review slot selected out of original-initial/original-rerun/grant-scoped order; a later slot missing its prior receipt, sealed/remaining lineage set, exact repair delta, accepted review impact map, affected/unchanged surfaces, finite consumers, or reuse identities; a grant-scoped request before both original slots were consumed; a missing, stale, pending, opinion-incomplete, reused, or target-mismatched newest plan record or grant identity; a duplicate same-target opinion/pass; or any other ineligible extra pass. A manifest, later-slot intake, or grant-record defect must block before dispatch and consume no semantic attempt, repair token, original review slot, or grant-scoped pass. A review request cannot authorize repair, another review loop, or shipping.

When contradictory current governing authority makes expected behavior indeterminate, return INCONCLUSIVE to the authority owner without classifying a blocker or advisory, authorizing repair, or completing.

## Procedure
1. Recheck all authority, target, verification, integration, assurance, identity, budget, prior-review, selected-slot, finite-consumer, and once-bound rule/target manifest entries against current bytes; when applicable, recheck the newest persisted exhaustion record/current grant and every later-slot intake identity. Require original-initial before original-rerun and both original slots consumed before a grant-scoped pass; the grant must be the current record's `continue` or completed `same-route` Second opinion for the exact inspected target. If any load-bearing input changed outside the accepted proof/review impact maps and D03 grant contract, return `INCONCLUSIVE`; never rebuild a manifest or infer rule, lineage, reuse, or grant state from filesystem discovery beyond bound references.

Recanonicalize the bound recipes and rehash each non-`none` adapter before consuming verifier receipts. Missing or drifted recipe, adapter, target, or doctor provenance returns `INCONCLUSIVE` to its owner. Never rerun doctor and never treat a doctor receipt as review or criterion evidence.
2. Confirm that the immutable assurance arrangement requires review. Reject compact. Standard uses a reviewer identity distinct from the verifier; high-consequence uses decorrelated non-implementer identities, fresh contexts, and role-specific Context Packs/prompts. High-consequence uses different equivalent Role Profiles or model families when available, discloses any same-model residual, and stops only when the Task Contract explicitly requires model-family separation.
3. Review **Standards** independently: correctness, security, privacy, data-loss/regression risk, project rules, maintainability required by those rules, evidence completeness, and the complexity lens below. Apply the lens inside this sole final pass, never as another stage or pass:

   | Primary tag | Evidence-backed replacement |
   |---|---|
   | `delete` | remove unnecessary code/artifact while preserving the full contract |
   | `reuse` | use an existing local helper/pattern |
   | `stdlib` | use an applicable standard-library facility |
   | `native` | use a native platform facility |
   | `yagni` | remove speculative behavior/generality absent from authority |
   | `shrink` | use a smaller direct implementation when no more specific tag applies |
4. Review **Specification** independently: every governing requirement, acceptance criterion, interface, migration, constraint, non-goal, approved scope boundary, and the bound Compatibility and degraded behavior block. Compare the immutable target and verification evidence with that block; never select a compatibility or degraded-behavior policy.
5. For `original-initial`, finish one independent pass across the whole declared scope, classify every observation, and seal every finding lineage. Lineage identity is the violated contract or invariant; trigger and expected/observed predicate; observable consumer or affected parent `AC-...`; causal boundary; finite current consumer/callsite map when the claim spans consumers; and originating target and evidence identity. Paths are evidence, not identity. For `original-rerun | grant-scoped`, freshly review closure of every remaining lineage and every surface reached by the accepted review impact map. Reuse original review evidence only for byte-, authority-, contract-, and dependency-identical unaffected surfaces. Review any repair-caused regression on its impacted surface, but do not turn the later slot into a new broad audit or substitute verifier receipts for either axis verdict.
6. Keep D22 finding classification unchanged, then classify lineage and repair admission separately. An outcome-relevant blocker still requires direct behavioral or direct static evidence that an existing parent `AC-...` or observable changed-contract consumer is broken, mapped to affected parent criteria or `affected AC: none` plus its exact fixed contract/consumer. In a later slot, incomplete closure of a sealed lineage remains `CHANGES REQUIRED` and same-outcome repair-eligible. A new lineage is repair-eligible only with direct causal evidence from the exact repaired revision, exact changed bytes or contract delta, accepted D04 impact-map edge, observable failure path from that delta, and fresh affected proof. A grant or changed hypothesis is authority, not causal evidence. A disjoint non-outcome observation is a terminal advisory. Independently serious safety returns separate-authority intake and never consumes the parent repair set. A disjoint outcome-relevant non-safety defect remains `CHANGES REQUIRED`, keeps the parent incomplete, and is authority-change-required rather than same-outcome repair-eligible.
7. Deduplicate every stable lineage and finding ID once and emit both axes against the same immutable target. Aggregate `APPROVED` requires both axes `PASS`, every prior lineage closed, no repair-caused blocker, no disjoint outcome-relevant blocker, and valid unchanged-surface reuse. Return incomplete existing or directly evidenced repair-caused blocker lineages to the backend for the one eligible consolidated same-outcome repair. Return a disjoint outcome-relevant non-safety lineage as `CHANGES REQUIRED` with `authority-change-required` to the outcome authority and no repair, verification restart, learning, approval, or completion. Return indeterminate authority to its owner, serious safety to separate-authority intake, and advisory-only approval to the already-scheduled terminal assessment. Review never schedules repair, maintenance, learning, or shipping. Portable `continual-learning review` is distinct, is never invoked by `dev-code-review`, and cannot add a review pass or profile tail.

## Verdict

```text
Standards: PASS | FAIL | INCONCLUSIVE
Specification: PASS | FAIL | INCONCLUSIVE
Overall: APPROVED | CHANGES REQUIRED | INCONCLUSIVE
```

`APPROVED` requires both axes `PASS`, every sealed prior lineage closed, no repair-caused or disjoint outcome-relevant blocker, and valid byte-, authority-, contract-, and dependency-identical unchanged-surface reuse; terminal advisories may remain. Any axis `FAIL` yields `CHANGES REQUIRED`; any axis `INCONCLUSIVE` yields overall `INCONCLUSIVE` unless another axis already establishes a blocking failure. Verifier receipts cannot substitute for either axis or Overall.

## Finding policy

D22 classification remains unchanged across all slots. Same-outcome blocking findings include specification nonconformance; correctness, security, privacy, data-loss, or regression risk; violated project rules; stale, unverified, incomplete, or contradictory evidence; and unauthorized scope or destructive behavior only when direct behavioral or direct static evidence proves that an existing parent criterion or observable changed-contract consumer is broken. Each blocker maps to affected parent `AC-...` IDs, or to `affected AC: none` plus its exact fixed contract and observable consumer.

Finding lineage is predicate-bound, not path-bound: violated contract/invariant; trigger and expected/observed predicate; observable consumer or affected parent criterion; causal boundary; finite current consumer/callsite map when applicable; and originating target/evidence identity. A renamed path with the same predicate remains the same lineage; two predicates in one path remain distinct.

After original-initial, same-outcome repair admits only incomplete closure of a sealed lineage or a new repair-caused lineage with the exact repaired revision, changed bytes or contract delta, accepted D04 impact-map edge, observable failure path, and fresh affected proof. A grant or hypothesis alone cannot admit. A disjoint non-outcome observation is advisory. Independently serious safety is separate-authority intake. A disjoint outcome-relevant non-safety defect stays blocking but returns `authority-change-required`; it is never silently demoted or admitted to another parent repair cycle.

Observed unapproved break, removal, clean cutover, hard-failure behavior, or speculative shim, default, retry, or alternate path is blocking only when it meets the outcome-relevance boundary. Contradictory current governing authority that makes expected behavior indeterminate yields `INCONCLUSIVE` to the authority owner rather than a guessed blocker or advisory.

No-effect proof binds the declared causal pre/post boundary, included targets, and explicitly excluded mutable files. Later changes to excluded mutable files do not invalidate the proof. Unrelated pre-existing defects, unrelated dirty bytes, mutable sidecar drift, and unsupported suspicion are disjoint observations and follow the classification above.

Changed paths, prose, metadata, frontmatter, scanner-string equality, stale adjacent explanation, and self-referential consistency assertions alone are advisory. Advisories are terminal nonrequired naming, style, maintainability, future-improvement, or unrelated observations that do not threaten the approved outcome. They cannot mask a blocker, silently expand scope, consume the repair token, reopen work, or schedule maintenance.

Assurance controls verification/review separation, not topology. Compact has no review dispatch. Standard requires distinct verifier and reviewer identities. High-consequence additionally requires decorrelated attempts and capabilities under the Task Contract. Integration or ticketing alone does not choose assurance.

## Review Handoff

Use the common Handoff and add the parent outcome and exact criterion IDs; exact target and `final single-lineage | post-integration verified` kind; authority and evidence identities; immutable standard/high-consequence profile and selection evidence; inherited semantic-attempt/post-assurance repair state; selected review slot; original initial-review/rerun state before and after; current grant identity and its one-pass consumption when grant-scoped; backend-validated once-bound rule/target manifest references and current comparisons; bound Compatibility and degraded behavior block plus immutable target and verification comparison; every finite current consumer/callsite map and proof entry; verifier and reviewer identities; separation mode; both axis verdicts; overall verdict; sealed lineage set and closure state; later-slot prior receipt, exact repair delta, accepted review impact map, affected/unchanged surfaces, unchanged-surface reuse identities and validation when applicable; deduplicated finding IDs and admission dispositions; causal no-effect boundaries; advisories; residual risk; and exactly one next owner. Do not edit, reformat, merge, stage, commit, push, ship, or repair.

In the existing finding, authority-conflict, safety-intake, and advisory entries, carry each stable ID, lineage identity, current D22 classification, admission disposition, exact path as evidence, governing authority, affected existing parent `AC-...` IDs or `affected AC: none` plus the exact fixed contract and observable changed-contract consumer, direct evidence, causal boundary, repair causal chain when claimed, one primary complexity tag when applicable, and concrete contract-preserving replacement. Carry disjoint outcome-relevant findings as `CHANGES REQUIRED` plus `authority-change-required`, serious safety as separate intake, terminal advisories as residual risk, and authority conflict with its exact owner. This detail remains inside the one Review Handoff and changes no verdict, repair authority, metric, or delivery boundary.

## Stop and next owner

Stop for compact intake, stale or insufficient proof, unavailable governing authority, an unsatisfied assurance arrangement, a changed target, an omitted/rebuilt/extended/stale/mismatched rule or target manifest, an incomplete finite-consumer proof, an out-of-order original slot, missing later-slot lineage/impact/reuse intake, a missing or ineligible grant identity, a duplicate same-target pass, or any other ineligible extra pass. Return incomplete existing or directly evidenced repair-caused `CHANGES REQUIRED` lineages to `dev-implementation` when the parent repair contract remains eligible; return a disjoint outcome-relevant non-safety `CHANGES REQUIRED` lineage as `authority-change-required` to the outcome authority; return serious safety to separate-authority intake; return authority-conflict `INCONCLUSIVE` to its owner and other `INCONCLUSIVE` proof gaps to the evidence owner; return advisory-only `APPROVED` to the backend's already-scheduled noncompact tail. Advisories remain terminal; review never schedules or performs repair, maintenance, learning, or shipping.
