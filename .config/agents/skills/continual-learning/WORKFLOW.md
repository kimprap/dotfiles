# Continual-learning maintenance flow

This document is a human maintenance reference, not runtime authority. `SKILL.md` owns portable qualification and curation; the calling specialty owns scheduling and completion.

## Terminal sequence

| Work type | Learning position |
|---|---|
| Engineering compact | Skip learning; completion records `Learning: skipped for compact`. |
| Engineering standard or high | `dev-code-review` once, `dev-verification` once, then `dev-continual-learning` once. |
| Specialty with its own adapter | The adapter is the only assessment caller. |
| Explicit portable review or Deep work | Run only under that explicit mode and authority; it is not a completed outcome's second assessment. |

The engineering adapter passes the settled outcome, affected paths, lean Handoffs, every papercut result, and complete Learning Candidates to portable `assess`. The portable body does not receive manifests, digests, counters, receipts, retry identities, or archive locators.

## Ownership

| Concern | Owner |
|---|---|
| Route placement and one-call scheduling | Calling specialty; `dev-continual-learning` for engineering |
| Candidate qualification, redaction, destination choice, curation, and checks | `continual-learning/SKILL.md` |
| Repository-friction discovery and ledger persistence | `papercut` |
| Success validation and five-field input construction | Calling specialty |
| Mechanical five-field rendering | `completion-presentation` |

Papercut and learning remain separate. Every completed repository-work boundary gets its one papercut look, including a learning Handoff that changed repository guidance, but that look never schedules a second learning assessment.

## Outcomes

| Learning status | Completion effect |
|---|---|
| `curated` | Continue. |
| `no durable learning` | Continue. |
| `blocked <ordinary reason>` | Continue and report the reason as residual risk. |
| `blocked <current governing-rule conflict>` | Stop only when the conflict makes the implementation invalid or unsafe. |

There is no learning retry, resume loop, second curator, session score, transcript scan, or learning ledger. Executable skills remain authoritative when this reference and runtime text disagree.
