# Papercut activation

Notice plausible repository-owned reusable friction during current dev, product, custom, or direct work. Current includes the active attempt and the bounded execution lineage ending at its work-task Common Handoff.

After every work-task Common Handoff is emitted, apply this rule exactly once as a soft look. Start with the completed attempt. Inspect its lineage only when directly referenced structured evidence shows an exhausted attempt or repair budget, recurrence of the same blocker class, loss of an otherwise completed result before persistence, or repeated new human authority needed solely to overcome execution mechanics. Read only the current plan blocker table, Common Handoffs from that work lineage, and immutable attempt receipts they reference; never mine transcripts, histories, memory, provider logs, or repository- or session-wide state. These markers permit inspection but do not establish qualification.

Consolidate repeated symptoms by stable surface and root-cause class. Keep attempt IDs, hashes, timestamps, provider or model details, and paths in evidence only. A clean final attempt does not erase earlier severe structured friction. When repository-owned final accounting considered only terminal observations despite an escalation marker, treat that qualification surface itself as a plausible run-lineage-blindness candidate. If at least one candidate qualifies, load `papercut` before the terminal response, select at most one for automatic capture, bind the single compact result to that Handoff, and retain its accounting in deterministic work-Handoff order.

The same work child owns the look; the root falls back only when that child is unavailable. No candidate means no skill or ledger access and no papercut output. The look and any capture change no task state and are never a task, Methods token, workflow or route stage, todo phase, assurance event, or per-task continual-learning trigger.
