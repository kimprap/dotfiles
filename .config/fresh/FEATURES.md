# Fresh profile features

One row per feature of this profile. Each row has exactly one case, `tests/cases/<Case>.py`, which asserts the behavior through keys, rendered cells, saved bytes or probe state. `uv run --script .config/fresh/tests/run.py drift` enforces the 1:1 correspondence.

Status: `native` is stock Fresh config or behavior with no repo code; `workaround` is repo code compensating for missing upstream behavior; `upstream-limitation` is behavior blocked upstream with no workaround built, whose case asserts the desired behavior and reports `LIMIT` until it passes (`LIFTED`).

## Upstream limitations

- diff-view-wrap: Alt+Z has no effect in diff and review views in 0.5.1, and the v0.5.2 release notes list no fix; no workaround is built — evidence https://github.com/sinelaw/fresh/releases/tag/v0.5.2
- dup-multicopy-undo: plugins have no general undo-grouping API (the only grouped edit, `replaceInFile`, saves), so multi-copy duplication cannot be one undo step; no workaround is built — evidence https://github.com/sinelaw/fresh/blob/v0.5.2/crates/fresh-editor/plugins/lib/fresh.d.ts
- duplicate-lines: retirement blocker — the native duplication carets fix is open and unmerged — evidence https://github.com/sinelaw/fresh/pull/3244
- comment-json-save: third-party limitation — Prettier drops the comma before a commented last JSON property, so uncommenting it and saving yields invalid JSON; the case asserts the formatted save and the kept comment only; no workaround is built — evidence the T3 characterization run of `tests/cases/comment_json_save.py` on 0.5.1
- explorer-icons: on 0.5.1 `pre_command`/`post_command` never fire, so plugins cannot react to the native explorer refresh; external creates inside subfolders get glyphs only on the next explorer change or save; no workaround is built — evidence the T5 attempt-2 hook trace of `tests/cases/explorer_icons.py` on 0.5.1 (15 hooks traced; neither command hook fired across Ctrl+R) and https://github.com/sinelaw/fresh/blob/v0.5.2/crates/fresh-editor/plugins/lib/fresh.d.ts
- review-diff: user keybindings with `when: mode:review-mode` or `mode:review-diff` are inert on 0.5.1, so the repo keeps none and Shift+Tab reverse focus is native — evidence the T4 repair run of `tests/cases/review_diff.py` on 0.5.1
- search-selection (also `interaction-highlights`, whose Cmd+G yellow check shares the cause): on 0.5.1 plugin overlays get a fixed priority of 10, the same as native search matches, and equal-priority draw order is unstable after `swap_remove`, so the yellow current match is sometimes drawn under the native grey and `search_selection` can fail at `first match yellow, second grey`; the feature and case are kept unchanged. Lift: when a release honours plugin overlay priority or makes tie order stable, bump-fresh verifies `search_selection` passes 20/20 solo and removes this entry — evidence https://github.com/sinelaw/fresh/blob/v0.5.1/crates/fresh-editor/src/app/plugin_commands.rs (`handle_add_overlay`, `priority: 10`), https://github.com/sinelaw/fresh/blob/v0.5.1/crates/fresh-editor/src/app/search_ops.rs (`with_priority_value(10)`), https://github.com/sinelaw/fresh/blob/v0.5.1/crates/fresh-editor/src/view/overlay.rs (unordered set, `swap_remove_at`), https://github.com/sinelaw/fresh/blob/v0.5.1/crates/fresh-editor/src/view/ui/split_rendering/orchestration/overlays.rs (sort by priority only)
- file-chords: the bundled `markdown_source.ts` checks the window mode against a stale state snapshot before setting it. On 0.5.1 and 0.5.2, closing a diff with q sometimes leaves a Markdown buffer outside `markdown-source` mode until it is activated again, so `file_chords` can fail at `q to return from the diff to notes.md`. The feature and case are kept unchanged; no workaround is built. Lift: when `updateMarkdownMode` stops relying on the stale read, bump-fresh checks that `file_chords` passes 20 of 20 solo runs and removes this entry — evidence https://github.com/sinelaw/fresh/blob/v0.5.2/crates/fresh-editor/plugins/markdown_source.ts#L324-L347 and https://github.com/sinelaw/fresh/blob/v0.5.2/crates/fresh-plugin-runtime/src/backend/quickjs_backend.rs#L5701
- explorer-icons (E1 file-handle check): on macOS Fresh's kqueue watcher (`notify` 8.2) treats a write in a watched folder as a new entry, watches an existing subfolder recursively, and keeps those descriptors. One save in a 2,000-entry tree under `ulimit -n 256` leaves about 230 descriptors open, so a later open can fail with `os error 24` (about 1 in 15 to 1 in 30 runs; 0.5.1 is triggered by our root watch, 0.5.2 also by its native root watch). The feature and case are kept unchanged; no workaround is built. Lift: when `notify` fixes #644 or Fresh stops using kqueue, bump-fresh checks that `explorer_icons` passes 30 of 30 solo runs and removes this entry — evidence https://github.com/notify-rs/notify/issues/644, https://github.com/notify-rs/notify/blob/notify-8.2.0/notify/src/kqueue.rs#L175-L191 and https://github.com/sinelaw/fresh/blob/v0.5.2/crates/fresh-editor/src/app/plugin_dispatch.rs#L245

### Log-guard signatures

- `unknown baseline id`: Fresh's plugin off-loop runtime rejects when a diff/review view or a bundled git plugin releases its baseline early; no repo code uses baseline APIs — evidence string in the 0.5.1 binary next to `crates/fresh-editor/src/app/plugin_offloop.rs`
- `baseline released during load`: same origin — evidence string in the 0.5.1 binary at `crates/fresh-editor/src/app/plugin_offloop.rs:61`

### Known intermittent failures

A swap by `bump-fresh` tolerates a candidate test `FAIL` only for a case listed here whose first failure message starts with the quoted prefix; the named limitation above explains it.

- `search_selection`: `timed out after 5s waiting for first match yellow, second grey` — search-selection
- `interaction_highlights`: `search: current match yellow #FAFD54, others #DCDCDC on #656565` — search-selection
- `file_chords`: `timed out after 5s waiting for q to return from the diff to notes.md` — file-chords
- `explorer_icons`: `E1: no 'os error 24' in a 2,000-entry tree under ulimit -n 256` — explorer-icons
