# Improvement Plan: Add one cross-harness skill-craft skill

**Datetime**: 2026-06-16-1608
**Mode**: standard
**Scope**: Create a reusable agent skill for creating, updating, evaluating, and cleaning up agent skills.
**Summary**: Add one concise, cross-harness `skill-craft` skill under `.agents/skills/`, with frontmatter guidance prioritized and lifecycle details split only where progressive disclosure helps. The skill should encode recurring guidance from OMP docs, Agent Skills docs, Anthropic `skill-creator`, Warp `update-skill`, and steipete `skill-cleaner` without copying their long eval tooling wholesale.

## Decision: one skill, not multiple

Use a single skill named `skill-craft`.

Why:
- Creation, update/refinement, evaluation, and cleanup all share the same core contract: inspect `SKILL.md`, preserve or design frontmatter, keep instructions concise, validate with realistic usage, and avoid stale duplicates.
- Splitting into `skill-create`, `skill-refine`, and `skill-cleanup` would duplicate the frontmatter schema and iteration loop, increasing drift risk.
- Progressive disclosure handles the size concern: keep the body as a lifecycle router and move only detailed evaluation/cleanup mechanics into one-level `references/` files if needed.
- The name starts with `skill-`, so it still groups naturally with any future split skills.

Split later only if real usage shows the single skill over-triggers or exceeds the concise body target. If that happens, use names `skill-create`, `skill-refine`, and `skill-cleanup`, with shared text minimized and copied deliberately.

## Frontmatter first

The final `SKILL.md` should prioritize a frontmatter section before workflow details. It should document both the canonical skill frontmatter template and the cross-harness field catalog.

Field handling guidance to include in the skill:

| Field | Harness/source signal | How to use |
|---|---|---|
| `name` | Agent Skills, Warp, Anthropic, OMP | Required. Kebab-case, <=64 chars, no leading/trailing/consecutive hyphens, match directory. Preserve on update. |
| `description` | Agent Skills, Warp, Anthropic, OMP, Codex/OpenClaw budget | Required. <=1024 chars. Primary trigger. Include what + when, concrete trigger nouns, near-boundary contexts; concise but slightly pushy. |
| `license` | Agent Skills spec | Optional. Short SPDX-like value or bundled license reference. |
| `compatibility` | Agent Skills spec, Anthropic | Optional. Include only real environment/product/dependency constraints, <=500 chars. |
| `metadata` | Agent Skills spec | Optional key-value map for version/tags/source/owner; prefer this over random top-level custom keys. |
| `allowed-tools` | Agent Skills spec experimental | Optional and conservative. Do not grant broad destructive tools unless the skill truly needs them. |
| `globs` | OMP skills/rules metadata | Optional. Helpful for OMP/UI/path association; ignored elsewhere. |
| `alwaysApply` | OMP skills/rules metadata | Usually `false` for normal skills; `true` only for tiny universal guidance. |
| `hide` | OMP skill metadata | Usually `false`; `true` hides from model prompt list while leaving skill accessible. |
| `disableModelInvocation` / `disable-model-invocation` | OMP / Agent Skills-style metadata | Usually `false`; include both spellings if exhaustive compatibility is desired. |

Notes:
- Unsupported fields are expected to be ignored by most harnesses, but broad or risky supported fields such as `allowed-tools` still need restraint.
- Keep actual descriptions single-purpose and budget-aware; steipete's cleanup workflow specifically preserves trigger nouns while compacting text.

- Anthropic `skill-creator`: https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md

Recurring high-signal criteria:
- Skill shape: one directory, required `SKILL.md`, YAML frontmatter, Markdown body, optional `scripts/`, `references/`, `assets/`, `evals/`.
- Progressive disclosure: metadata loads first; body loads on activation; references/scripts load on demand. Keep `SKILL.md` lean. Warp target: ~150-200 lines. Agent Skills/Anthropic target: under 500 lines or 5000 tokens.
- Description quality controls activation. Include what the skill does, when to use it, trigger nouns, and adjacent contexts. Avoid vague descriptions and over-broad keyword traps.
- Good skills come from real work: extract successful steps, user corrections, I/O formats, project artifacts, failure cases, and recurring review feedback.
- Skill body should add what the model lacks: project/domain specifics, concrete workflows, gotchas, output templates, validation loops. Do not explain generic concepts.
- Prefer procedures over declarations: clear defaults, ordered workflows when order matters, examples/templates when output format matters, and reasoning for fragile constraints.
- Avoid menus. Pick one default approach; list alternatives only as escape hatches.
- Evaluation loop: start with 2-3 realistic prompts, compare with baseline or previous version, add objective assertions after seeing outputs, grade with evidence, inspect transcripts for wasted work, iterate.
- Description optimization: use ~20 realistic trigger queries with positive and near-miss negative cases, split train/validation, run multiple times if practical, pick the best validation performer.
- Scripts are for repeated deterministic work. They should be self-contained, noninteractive, documented with `--help`, use structured stdout and diagnostics on stderr, have helpful errors, idempotency, dry-run for destructive work, safe defaults, and predictable output size.
- Cleanup workflow: audit live loaded inventory before filesystem guesses, find duplicates/stale skills/long descriptions/disabled roots, verify the kept copy exists and is loaded, suggest before deleting, preserve trigger nouns, and never delete ignored/untracked skills without a destination or explicit confirmation.

Dropped as lower-signal for the first implementation:
- Full Anthropic eval viewer machinery and benchmark scripts.
- Long UI/browser-specific guidance for Claude.ai/Cowork.
- Analyzer implementation from `skill-cleaner`; include workflow shape first, script only if later needed.
- Exhaustive examples from all repos; one compact example per pattern is enough.

`SKILL.md` target outline:

1. Title and one-line purpose.
2. `## Frontmatter first` with canonical template and rules.
3. `## Triage` routing:
   - New skill: capture intent, source material, output, trigger conditions, verification.
   - Existing skill: preserve name, inspect current behavior, revise targeted sections, snapshot/baseline when evaluating.
   - Cleanup: audit loaded roots, descriptions, duplicates, usage evidence, and deletion risk before edits.
4. `## Authoring rules`:
   - keep body lean;
   - add only what the model lacks;
   - prefer defaults over menus;
   - put gotchas/templates/checklists inline when they are activation-critical;
   - move detailed docs/scripts to one-level references.
5. `## Evaluation loop` compact summary with 2-3 prompts first, baseline, assertions, grading evidence, transcript inspection, iterate.
6. `## Cleanup loop` compact summary with loaded inventory first, duplicate/stale/long-description candidates, verify kept copy, suggest before deleting.
7. `## Scripts policy` concise criteria for when to bundle scripts and how they must behave.
8. `## Done criteria` for any created/refined/cleaned skill.
