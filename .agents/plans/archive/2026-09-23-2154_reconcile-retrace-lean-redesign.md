## Scope and effects

- Scope: T1 changes Reconcile and every shared file that names both skills, so T2 changes only Retrace. Splitting T1 further would leave the Reconcile skill, reviewer protocol, reviewer agents and evals on different grammars with no independently checkable state, and one fresh owner can hold that set. T1 also carries the declared C6 supervisor change, a behavior expansion beyond probe removal inside the existing T1 targets. Every dispatch brief copies the spec's user-intent sentence and verbatim user decisions word for word. Live runs D1 (standalone conversation), D2 (standalone artifact: different mode and starting state) and D3 (delegated Retrace path, root push, scheduling and nested disposal) each prove runtime behavior that static inspection cannot; D3 does not subsume D1 because it never exercises standalone brief approval or standalone output. Probe removal settles the probe assertions in `lifecycle-plugin.test.js` as `remove` (they defend only the deleted mode) and keeps the production-prompt, large-reply and `delivery-unknown` assertions. One permanent test is added to that file as `keep`: it defends the rule that a `terminal: false` scope reply skips only the owned-child disposal gate. A plausible bug it catches is a nonterminal reply that frees the scope's slot, allows a second reply, or leaves the terminal gate open. The closest existing test, `disposes observed stock processes before parent replies`, covers only the terminal gate. Eval edits cover affected assertions only; no full-catalog run is added.
- Effects: Repository edits to the listed targets only, including deleting `.config/agents/skills/reconcile/references/execution-flow.md`. Model and account use by the implementation, review and verification agents and by the lifecycle worker processes of D1–D3. D2 writes and then removes one temp file outside the repository. In D3 the Retrace root uses Eval with `tool.lifecycle` to capture sources, frame requests and dispatch. In-run human approvals (the D1 and D2 Reconcile briefs and the D3 scope table) are relayed to the human through Main.
- Non-goals: The `dev-ask` and `dev-implementation` skills and maps; `return.md:51-74`; `lifecycle-consumers.js`, `lifecycle-plugin.js` and `fixtures/lifecycle-rpc-worker.js`; the scope sentences in ADR-0001 (including `:93`) and ADR-0003; ADR-0004 `:62`; `scan_stale_contracts.py`; CLOSED plans, earlier specifications, proof artifacts and the plan-0019 packet folders; an upward-fetch channel operation, persistent store or parser service; late-reply admission after `delivery-unknown`; an immediate-stop exception to C4; any narrower evidence size or source-type eligibility; any other new mechanic, gate, compatibility shim or proof mechanism; native proof runs beyond D1–D3 and full-catalog eval runs; Git staging, commit, push or other shipping.
