**Confirmed operative proposal**

1. **Outcome, not a delivery slogan.** Reconcile/Retrace should complete, or stop with a precise cause, without losing admitted results, replaying uncertain work, or starting repair cycles because of harmless presentation differences. Do not promise that every review converges or that an unrecorded failure is always recoverable.

2. **Keep acpx/native OMP and two application responsibilities.** The supported native transport adapter owns session handles, request correlation, journal observation, cancellation, and observed disposal. One coded semantic controller owns approved bindings, reviewer progression, scopes/dependencies, budgets, candidate application, freshness, validation, and admission. Logical ownership does not require physical controller-process nesting. No new supervisor, mailbox, broker, acknowledgement exchange, or independent receipt ledger.

3. **Reuse native `yield`, not a custom result extension.** The proposed effective tool set is `read`, `glob`, `grep`, `yield`, with extension discovery still disabled and the rest of the approved isolation intact. The model supplies judgments and required content in explicit `yield.data`. Code supplies request/session/owner/phase/revision bindings and terminal scope status. A small domain schema has variants for the existing review/evaluation exchanges; it is not another negotiated protocol language. Structure the fields needed for decisions and validation; retain Correction/report payloads intact. No model-authored hashes, receipt echoes, delimiter-counting, or lifecycle declarations.

4. **Controller validation remains authoritative.** A successful native tool call is successful submission, not a `VALID` review verdict or application approval. Native `yield` supports last-turn extraction, incremental submissions, and schema-override behavior: none may become a final semantic result here. Require complete explicit data, reject data-less/prose-fallback and incremental finalization, and never let a native schema override waive application validation. Retain the existing original-expectation invalid-return/re-ask budget; request/tool IDs cannot reset it, and re-observation cannot consume it. Do not turn a missing verdict into `REVISE`, `BLOCKED`, or success by default. A native `yield` ends a prompt cycle, not the reviewer session; observe turn settlement and reuse separately.

5. **One authoritative result boundary.** Use the completed native result tool's structured output, associated with the owning acpx request and native tool-call identity, as the submission boundary. In the tagged source this is carried in ACP `tool_call_update.rawOutput`, including `details.data`; do not parse the displayed tool-content preview. Associate the completion with the actual native tool invocation and owning session/request, not model-authored identity fields or unauthenticated producer hints. Validate and retain the result with its machine-owned binding before admitting once, advancing dependent work, or deleting temporary evidence. The native journal is the replayable transport record; the controller's retained result is application state, not a second transport log. No automatic controller-crash recovery or power-loss guarantee is added.

6. **Integrity without cross-representation equality.** Human rendering and persisted assistant-text projections are not interchangeable byte oracles. Remove universal `live text = watch text = session text` as admission authority. Independently check exact payload integrity at the designated structured boundary; real missing, truncated, duplicated, or misrouted content remains a defect. Do not globally trim, normalize whitespace, or repair missing content. A wrapper newline is presentation; a newline inside a proposed artifact is payload. Code still owns hashes for artifact identity, drift, and evidence integrity. Native session evidence remains relevant to request identity, restoration, and diagnostics. Preserve required credential removal and transitive parent relinking wherever session copies are retained; do not inspect or retain credentials.

7. **Recover observation, never uncertain execution.** After observer loss, re-watch the original request using the supported journal and opaque cursor. A lost acknowledgement alone does not permanently disqualify a provable original result. Resolve KS3/KS8 in favor of this recovery, without accepting a foreign, superseded, already-admitted, or explicitly terminated request as fresh work. Retain an admitted first result even if later turn finalization fails; reuse and cleanup remain separate. If the outcome cannot be established, stop the affected request and preserve successful siblings. No prompt replay, fresh reviewer, reconstructed conversation, fallback collector, or automatic allowance reset. Same-ID restoration must use the actual native session semantics; do not invent an extra provider-side chat identifier or claim that an unchanged ID proves unlimited lossless context. Known native persistence limits remain relevant.
