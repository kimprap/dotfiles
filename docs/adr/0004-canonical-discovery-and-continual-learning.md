# Canonical discovery and continual learning

**Status:** ACTIVE  
**Date:** 2026-08-09  
**Updated:** 2026-08-25
**Decision IDs:** D07, D23  
**Related authority:** ADR-0001 D01, D15

## Scope

This decision governs conditional discovery of the generic engineering workflow's current contracts and ADR registry, focused decision provenance, and Standard versus Deep continual-learning maintenance, including the frozen evaluation boundary for mutating curation. It applies to the repository-local `.agents/AGENTS.md` pointer, `docs/adr/INDEX.md`, active workflow ADRs, `dev-continual-learning`, the backend curation seam, and the current workflow reference. It does not make ADRs runtime state, require eager loading, authorize background curation, turn repository evidence into memory or authority, or permit mutation of `/Users/kim/.agents/AGENTS.md`.

## Context / problem

Repository-local guidance can be injected automatically, but workflow references and ADRs are not necessarily in ordinary agent context. Loading all workflow history for every task would waste context and give rejected or superseded records an opportunity to masquerade as executable policy. The generic workflow therefore uses one conditional repository pointer: agents changing or diagnosing it read `.config/agents/skills/dev-ask/WORKFLOW.md` and `docs/adr/INDEX.md`, while ordinary tasks read only their applicable skill/rule and the active ADRs named by their Task Contract. The index is a stable, human-readable, non-executable registry; active skills/rules and current `WORKFLOW.md` own current behavior, focused active ADRs own durable rationale, approved requirements/specifications/direct authority govern their concerns, and Atlas or external sources remain advisory. At completion, narrow evidence can justify a focused rule or contract repair, but invocation counters, calendar audits, transcript mining, or broad “self-improvement” claims would create hidden state and unbounded maintenance.

## Decisions

### D07 — Deep continual learning

- **Scope:** Portable `continual-learning` assess/review/deep semantics, the thin `dev-continual-learning` adapter, maintenance boundaries, validation, output, skill-local evaluation, and guidance specificity.
- **Decision:** After a settled standard or high-consequence engineering outcome, the one route-visible `dev-continual-learning` adapter invokes portable `continual-learning` mode `assess` exactly once. Compact never dispatches the adapter; it completes after criterion-complete smoke. Any mutating Learning Candidate discovered during compact work is deferred to a separately approved standard or high-consequence maintenance route so durable guidance still receives its bound evaluation, independent verification, and final review. The portable skill is the sole owner of assess eligibility, candidate qualification, affected-artifact scope, mutation procedure and proof, safe restoration, Deep eligibility, and terminal result semantics; the adapter supplies engineering Task Contract, Context Pack, Common Handoff, current-manifest, selected-slot, counter, stage, and receipt mappings without forking those semantics. Before a mutating curator is ready, require the Learning Candidate reporter to supply one complete source/independent-adjacent evaluation proposal; the lifecycle caller validates reporter authority, freshness, completeness, adjacent-case independence, and proof classification, then freezes its canonical tuple and SHA-256 under Task Contract `Verification` and in the exact Context Pack. Reuse settled source evidence only while target revision, environment, expectation, proof method, and evidence integrity still match; always run the independent adjacent case fresh before mutation, then rerun both cases against unchanged expectations afterward. Deterministic facets need no separate evaluator; each semantic facet requires one fresh read-only non-curator reasoned result within the same curation task. Complete proof yields `CURATED`; a stable deterministic failure restores only the curator's exact delta when safe and yields `NO DURABLE LEARNING`; stale, missing, tampered, flaky, inconclusive, missing-semantic-verdict, or unsafe-restoration evidence yields `BLOCKED` with an exact resume condition. Preserve the existing one curation task, Common Handoff, three outcomes, and exact seven-field payload in this order: `Updated`, `Added`, `Removed`, `Skipped`, `Validation`, `Deep candidate`, `Papercut outcome`; `NO DURABLE LEARNING` is also valid when no mutating candidate exists. A separately authorized engineering Deep route invokes portable mode `deep` through the same adapter. Portable `review` requires its own explicit evidence pointer and is not code review, papercut review, or a profile-tail pass. Prefer the least-specific sufficient verified guidance that covers the source and held-out near misses under approved authority; this is a bounded curation heuristic, not Bennett's formal weakness metric or a claim of autonomous learning, memory, reflection, or generalization.
- **Decision:** A numbered `dev-continual-learning` profile-tail row consumes the one existing terminal Standard assessment; when that row is absent, the backend schedules the same adapter assessment once. The route-visible owner and Common Handoff remain unchanged, and the adapter invokes portable `assess` inside that task rather than adding a portable row, pass, state, or Handoff. Papercut capture, including the soft post-work-Handoff look, never triggers an assessment or any per-task learning dispatch.
- **Decision:** When a complete Learning Candidate originates from papercut evidence, the lifecycle caller preserves its immutable `PC-ID` through the existing curation contract and supplies it to the portable assessor. The portable assessor returns that exact ID and candidate-specific mapping evidence without reading or writing the ledger. After the authoritative terminal result, the backend settles only that exact record through the portable papercut interface: `CURATED` or another verified durable correction maps to `fixed`; a candidate-specific final rejection or failed frozen evaluation maps to `rejected`; replacement maps to `superseded`; and `BLOCKED`, incomplete, deferred, or non-candidate-specific outcomes keep the record open. Settlement is post-result evidence handling, not another curation state, authority grant, audit, retry, or workflow.
- **Decision:** Portable `assess` may maintain an existing repository-owned surface-verification adapter only when the caller supplies the already-authorized exact destination URI/digest and a complete frozen evaluation tuple. It may modify only adapter-owned files through `maintain-surface-verification-adapter` and `craft-skill`. It cannot create a missing adapter, change the shared contract or either wrapper, or turn product failure into maintenance authority.
- **Why:** Narrow evidence-backed terminal maintenance can repair current guidance without turning ordinary completion into a broad audit. Freezing reporter-authored expectations before curator dispatch prevents moving targets and self-grading; separating deterministic checks from fresh non-curator semantic judgment gives each claim the smallest credible proof owner without adding another lifecycle.
- **Rejected alternatives / why not:** Every-Nth counters, calendar audits, router-owned timers/state, background transcript mining, elapsed time, artifact volume, or unchanged Handoffs create hidden scheduling and mistake activity for evidence. Guidance-only anti-gaming, backend- or curator-invented expectations, curator self-grading, a separate semantic sidecar, a second evaluator for deterministic checks, post-change-only baselines, weaker thresholds, and skipped flaky cases can manufacture a pass instead of testing the frozen claim. Deep maintenance after every completion is an unbounded completion tax; a deep candidate blocks the current outcome only when an exact contradictory contract blocks correctness. User-level AGENTS, memory, credentials, and personal/global state are outside project authority. Automatic transcript-derived memory, a new memory backend, or SQLite learning state adds an unauthorized state service. Skill proliferation, duplicated volatile facts, and a rule per observed task lack a demonstrated recurring seam. Shortest prose, broadest rule, or a formal Bennett weakness score does not establish sufficient authorized guidance or LLM self-improvement. Blanket architecture surveys or grilling ignore route intent.
- **Consequences:** Standard and high-consequence engineering learning remains one narrow terminal adapter assessment with one portable curator and no recursive curation state. Compact has no curation task or Handoff; a mutating candidate is evidence for a separate approved maintenance route and cannot delay compact completion. On an eligible noncompact route, a mutating candidate is not ready without the exact caller-frozen proposal; source reuse and fresh adjacent proof are explicit, and only a complete deterministic/semantic result can yield `CURATED`. `NO DURABLE LEARNING` remains a valid terminal outcome, while unsafe or incomplete proof fails closed as `BLOCKED`. Deep maintenance is explicit or event-driven and separately authorized by default. Portable skill-local evals own assess/review/deep qualification, proof, output, stop, host-neutrality, and adapter-duplicate behavior; engineering evals own only adapter, dispatch, recovery, accounting, completion, compact exclusion, and settlement integration. Durable guidance proves the source and an adjacent/near-miss case on the least-specific sufficient project-owned surface. No curation runs in the background, mutates user-level state, creates a memory service, or implies shipping.
- **Consequences:** A terminal portable curation result can close its originating papercut through the backend's exact-ID settlement call, but cannot close unrelated records. Missing write authority or unsafe ledger state leaves the verified workflow outcome unchanged and the papercut open with a disclosed boundary.
- **Reopen when:** Portable assess/review/deep eligibility, adapter ownership, scope, payload, binding, proof ownership, source-reuse/freshness, outcome mapping, restoration, separate-route boundary, user-level exclusion, project-owned destination rule, skill-local evaluation ownership, or Bennett evidence limit changes; or background/count/calendar maintenance or a new memory/state authority is proposed.

### D23 — Focused decision provenance

- **Scope:** generic and stage-specific dev-workflow decision maintenance
- **Decision:** Keep `WORKFLOW.md` concise and current. Add a generic and stage-specific decision-authority map there. Store each durable choice once, in the narrowest ACTIVE ADR, using stable ID, Scope, Decision, Why, Rejected alternatives and why not, Consequences, and Reopen trigger. Add ID and scope discovery to `docs/adr/INDEX.md`; D24 follows the same rule in focused ADR-0007, which supersedes ADR-0006, and D27 follows it in focused ADR-0009. Keep superseded or rejected history in ADR status and supersession, not skills, memory, plans, transcripts, or one global decision ledger. A dedicated non-authoritative repository evidence ledger is not decision provenance and cannot own rationale or supersede an ADR. Preserve concurrent product-workflow ADR-0005 work outside this migration.
- **Why:** Future iterations get both rationale and rejected paths without duplicating executable contracts.
- **Rejected alternatives / why not:** Per-skill logs repeat generic choices; WORKFLOW history bloats current guidance; one ever-growing decision ledger blurs ownership; treating papercut evidence as authority or provenance would let observations bypass human decisions and focused ADR ownership.
- **Consequences:** Current behavior stays in skills and WORKFLOW; focused ADR decision units explain why and why not; the index and WORKFLOW map make the narrow owner discoverable. ADR-0007 D24 alone owns current cross-workflow papercut rationale, while its ledger remains evidence only; superseded ADR-0006 remains historical authority.
- **Reopen when:** Canonical workflow authority or ADR storage and supersession changes.
